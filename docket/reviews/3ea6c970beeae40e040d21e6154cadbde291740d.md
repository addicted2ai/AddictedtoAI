# Blocking finding

### B1 — `FRAME.md` fact 14 now contradicts itself about its own mechanism

The commit removed the string "three independent ways". It did not remove the
claim. Two carriers survive in different words:

**`FRAME.md:443–444`**, inside fact 14, nine lines below the sentence that
denies it:

> The heading is now **the third derivation**, so the command this file and
> `CLAUDE.md` both tell a reader to run is no longer the one with the hole in it.

**`FRAME.md:429–435`**, the Claim paragraph, same fact:

> … compared against a third value that is ***not* a derivation**: the number
> typed in this fact's own heading. … Calling the heading a third "independent
> way" would flatter it: it is the typed value under test.

One of those two sentences is false by the other's definition, and the commit's
own subject line — "fact 14 derives the count two ways, not three" — says which.

Second carrier, lower stakes because it is a comment rather than published
prose: **`scripts/check-governance-claims.mjs:466`**, the canary's `why` string
— "Round 177 made the heading that command's **third derivation**".

**Why this blocks rather than gets a note.** The behaviour is correct and
unaffected; this is terminology, not logic. I would normally carry it forward.
Three things make it different:

1. It is in `FRAME.md` — the file `CLAUDE.md` and the maintainer's global rules
   both designate as ground truth, whose stated promise is "loaded, not
   remembered" and whose preamble says a fact without a check or an attestation
   behind it does not belong in the file. Nothing checks fact 14's body prose;
   the registry anchor is deliberately the heading line alone, so this sentence
   is exactly as unguarded as the count used to be.
2. It is the *specific claim this commit exists to remove*, published under a
   commit asserting it was removed. Merging it would make the round's own record
   false about the round.
3. It is the round's own thesis turned on itself: an unchecked self-description
   drifting from the thing it describes. The fix was a grep for a string where
   the defect was a claim — the same string-versus-claim gap that let "21 rules"
   sit in three files while a checker watched two of them.

**The fix is two lines** and needs no re-derivation: reword `FRAME.md:444` to
say the heading is now checked against the two derivations rather than being a
third one, and the same in the `why` string at
`check-governance-claims.mjs:466`. Nothing in the check block, the registry, the
anchors, or the agent documents needs to move. I would expect a re-review of
this to be minutes, not a pass.
