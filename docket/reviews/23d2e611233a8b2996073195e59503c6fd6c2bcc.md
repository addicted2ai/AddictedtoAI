## Blocking finding 1 — `scripts/check-publishing-quota.mjs` reversion, undocumented and production-breaking

`git diff origin/main origin/loop/build/rounds-merged-counts-rounds --
scripts/check-publishing-quota.mjs` removes the entire degradation guard PR
#83 added (the try/rev-parse/WARN path) and wraps `git show origin/main:…` in
a try whose catch `fail()`s with "could not import origin/main:app/lib/posts.js
… (fetch origin/main and try again)". The file's mode flips 100755 → 100644.

I demonstrated the consequence without touching the tree: deleted
`refs/remotes/origin/main` (`git update-ref -d`), ran
`node scripts/check-publishing-quota.mjs` → "fatal: invalid object name
'origin/main'." / "FAIL could not import origin/main:app/lib/posts.js …", exit
1 — the same failure PR #83 measured and fixed. Restored the ref with
`git fetch origin main`; origin/main is back at 6ec241d (#83), the check is
green again with the ref present, and `git status --porcelain` is clean.

Why this breaks production: the check runs in `prebuild` (`package.json`),
which `npm run build` runs, which is what Vercel's production build runs on
its single-branch shallow clone — a checkout that has no `origin/main`, per
PR #83's own entry, the deleted docket item, and `vercel.json`. CI stays
green because `.github/workflows/pr-checks.yml` checks out with
`fetch-depth: 0` and has origin/main — the exact asymmetry under which every
deployment failed for ten and a half hours on 15 August. Merging this branch
re-starts that outage. Nothing in the round-126 changelog entry (read in
full) mentions the quota check, and PR #84's body is empty, so the change is
documented nowhere.
