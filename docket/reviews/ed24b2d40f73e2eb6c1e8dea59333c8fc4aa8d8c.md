## The fix

Read the new `check-review-artifact.mjs` in full. The REQUIRING/HONOURING
split is gone. Previously: non-`delegated` origins (or branches with no
changelog entry) were exempt from *carrying* a review, but a second,
always-on check still *honoured* any covering review that rejected. My prior
finding showed the honouring half's "covering" test (condition 4, exact-tree
match) meant a rejecting review could be trivially uncovered by one
unrelated commit, at which point `covering.length === 0` and the exempt
path's pass condition ("nothing covers HEAD, so nothing rejects it") was
satisfied vacuously. The new logic removes the exemption entirely: every
branch, regardless of Origin and regardless of whether it declares a
changelog entry, now needs some artifact in `covering[]` with
`Verdict: approve`. There is exactly one pass condition left, and it no
longer distinguishes "never reviewed" from "reviewed and rejected, coverage
since lost" — both now fail identically ("no review artifact covers the
merged tree"). This is the correct shape of fix: it removes the two-tier
policy that created the gap rather than patching the specific commit-count
edge case, so there is no smaller variant of the same shape left to find in
this mechanism (a narrower version of my own original finding — outrunning
coverage by N commits instead of 1 — would fail exactly the same way, since
"outrun" no longer buys anything: there is nothing to be exempt into).

is empty — zero lines, checked directly. Re-read `ship()`'s actual call site
at its current state (not the round's description of it): it calls

true for the reason the round gives: there was never a second
implementation to update in step.
