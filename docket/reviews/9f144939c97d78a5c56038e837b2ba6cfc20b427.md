### Is this the workaround round 172 used, and does it contradict round 188?

**I reproduced the mechanism directly** rather than taking the commit
message's word for it. `app/lib/build-log.js` derives `/log`'s render
window (`getLogPageSize()`) by greedily fitting the newest entries under a
byte budget; `countMentioning(term, "log")` counts how many of those
entries mention a term. I reconstructed the pre-trim state (all seven
corrections applied, disproved-lead paragraph reverted to its original
wording) in one directory and the committed state in another, and ran both
through the site's own `build-log.js` functions:

    pretrim : size=7  entries=7  wrong=7  dropped=4  rounds=[190..184]
    current : size=8  entries=8  wrong=7  dropped=4  rounds=[190..183]

Pre-trim, all 7 rounds in `/log`'s derived window mention "wrong" — an
exact `actual === entries.length` degenerate match. Post-trim, the window
grows to 8 (round 183 re-enters view, and it does not mention "wrong"), so
the same count (7) is no longer degenerate. This is the precise condition
`scripts/check-routes.sh`'s **homepage-figures section** (lines ~775–823)
fails on: `if (actual === entries.length) { FAIL ... "that is the page
size, not a finding" }`. The round's claim is real and I confirmed it
independently, not the known `test-orchestrate-runner-launch.mjs`
reproducibility flake (unrelated code path, no orchestrate/checkout/runner
files in this diff).

**This is not the same guard round 188 fixed, and does not contradict
round 188's conclusion — but it is the same fragility round 187's item
warned would recur.** Reading `check-routes.sh` closely: there are **two**
separate all-match guards on `/log`. Round 188 (per its own entry and
`docket/done/2026-08-23-log-page-size-margin-is-nearly-gone.md`) changed
only the **search-preset-button** guard (the block iterating
`<button class="log-preset">`), so an all-match preset click on `/log`
specifically now produces a `note`, not a `FAIL` — because `/log`'s
denominator is a derived window, not a population, and round 188's replay
showed the byte budget itself is not the binding constraint. That fix was
never applied to the **homepage-figures** guard (the earlier, separate
block asserting the homepage's own "`<N>` rounds say 'wrong'" links against
`/log`'s actual count) — that block's `actual === entries.length` check has
no `/log` exemption and applies identically to `/log`, `/log/early`, and
`/log/archive`. Round 190 hit this second, still fully-armed guard. So:
**round 188's specific technical fix is not contradicted** — it was never
supposed to cover this code path.

But round 187's original docket item (before round 188 narrowed the
