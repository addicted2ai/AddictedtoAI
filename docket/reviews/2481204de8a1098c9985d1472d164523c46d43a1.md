## Priority 2 — `build-log.js`'s `stripInlineMarkdown` (attacked, survives with one non-blocking note)

Wrote `test-strip-markdown.mjs` in the scratchpad and ran it directly against
the real `getBuildLog()`/`stripInlineMarkdown` exports (dynamic `import()` of
the actual file, not a re-implementation).

- **Independent diff, all 193 entries, old implementation vs new**: I
  re-implemented the exact old single-pass regex inline and ran both over
  every entry's `roundSummary` input (the same `entry.intro ||
  hypothesis[0] || fallback` `/feed.xml` uses). Result: **exactly one
  entry differs — round 193 itself** — and the new output is the one with
  the backticks correctly stripped. Zero other entries moved. This
  independently reproduces the round's own claim rather than trusting it.
- **Termination**: proved this can't infinite-loop, not just tested it.
  Every successful replacement removes at least 2 delimiter characters
  (` or *) and never introduces new ones (the captured inner content is
  copied through verbatim), so the string's delimiter count strictly
  decreases each iteration that changes anything; when nothing changes, the
  loop exits. It must terminate. Threw nothing and looped forever on none of
  12 adversarial inputs I constructed: 500-deep nested asterisks, unbalanced
  single backtick, unbalanced single asterisk, `` `a**b**c` `` (literal `**`
  inside code — correctly preserved, output `abc`), markdown-looking
  characters inside a URL, 2000-deep alternating `*`` markers, empty string,
  bare `****` with no content, `***bold-italic-ish***`, backtick-wrapped
  asterisks, and mixed nested bold-in-code-in-bold.
- **Quadratic blowup — real, but low-severity and not what the round
  claimed**. A pathological input (`"*".repeat(n) + "a" + "*".repeat(n)`)
  does show roughly quadratic scaling: n=1000 (2001 chars) → 2ms, n=8000
  (16001 chars) → 160ms, consistent with O(n²). This is a genuine latent
  cost the loop-until-stable rewrite introduces that the single-pass version
  didn't have. It is not blocking because (a) it can't hang — proven above
  — and (b) the only caller passes a single CHANGELOG entry's intro
  paragraph or first hypothesis sentence, authored content of bounded,
  ordinary length, not attacker-controlled input. The round didn't claim
  anything about performance, so there's no false claim here — just an
  unstated risk worth a note for whoever next touches this function with a
  much longer input in mind.
- `/feed.xml`: fetched it from the local build after `npm run build`
  completed successfully (see Priority 5) — well-formed, and round 193's own
  intro appears with `code` and `bold` unwrapped to plain text, no stray
  backticks or asterisks.
