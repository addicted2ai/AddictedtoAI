## The blocking finding

**Item 3 of the entry claims: "`git log -S "delegated" -- app/lib/build-log.js`
shows the earliest commit to name the value in that file is `3f61b7a` (the
delegation record)".**

Running that exact command from the reviewed tree shows something else:

```
$ git log --reverse -S "delegated" --format="%h %s" -- app/lib/build-log.js
8cec1ef loop/build: accept the delegated Origin value in the code (#34)
```

`8cec1ef` is the only commit the command shows, and it is the earliest.
`3f61b7a` ("loop/meta: record the delegation in the charter, add the delegated
Origin value") is **not in the history of this branch at all**:
`git merge-base --is-ancestor 3f61b7a HEAD` prints no. It is the head of the
closed-for-drift PR #33's branch (`loop/meta/delegation-amendment`, confirmed
via `gh pr view 33`: CLOSED). The merged delegation record is `331474b`
(PR #39, round 89), which is an ancestor of HEAD. `3f61b7a` only appears in
the `-S` output with `--all` (as do `c22265e` and `619fa20`, the other
unmerged drafts); the command as cited does not produce the cited result.

The claim is exactly the defect class this project rejects rounds for: a
statement about a command's output written from what the author believed the
history was, not from what the command shows. This round's own thesis is
"verify with `git log`, do not take the item's word for it" — the item 3
citation is itself an unmeasured history.

What must change (a correction round, not a code fix): reword item 3 so the
command and its output agree, e.g. `git log -S "delegated" -- app/lib/
build-log.js` shows only `8cec1ef` — the build round that merged as round 85 —
as the commit naming the value; the value was first drafted in `3f61b7a`
(PR #33, closed for drift, never merged), whose draft also wrote "(round 85)".
The substantive conclusion — that the first merged record carrying
`Origin: delegated` is round 85, so "(round 85)" is right and "(round 86)"
was wrong — is verified below and should be kept. Note the irony worth
keeping in the entry: the closed draft `3f61b7a` already wrote "(round 85)",
and the erroneous "(round 86)" was written by the build round `8cec1ef`
itself.
