## 1. The headline attack: `legacy/` is not pinned to the six files — it is a wide-open directory

I read `scripts/check-briefs.mjs` end to end first. The mechanism: it lists
`docket/briefs/legacy/` only to print a count (`legacyFiles.length`, used
solely in the summary line). The validation loop (`for (const entry of
briefFiles)`) walks `fs.readdirSync(briefsDir, ...)` **without recursing
into `legacy/` at all** — files inside it are never opened, never
filename-checked, never dated, never diffed against git history. Nothing
in the script or in `docket/briefs/README.md` claims otherwise; the README
says plainly "`scripts/check-briefs.mjs` does not check anything about
files under `legacy/` — not the header lines, not a premises section,
nothing," which is an accurate description of what I found in the code.
The problem is not that this is undisclosed — it's that the exemption has
no pin to the six specific files it was created for. I verified this three
ways, each reverted afterward with the working tree confirmed clean by
`git status --short`:

**Attack A — drop a fabricated, premise-free brief straight into `legacy/`:**
```
$ node D:/AddictedtoAI/scripts/check-briefs.mjs
docket/briefs/ check -- 1 current brief(s), 7 legacy brief(s) (exempt, see docket/briefs/README.md)
5 premise(s) checked: 2 cite FRAME.md, 2 cite a command, 1 cite an attestation
...
ok    all current briefs declare their premises
EXIT:0
```
A brand-new file (`docket/briefs/legacy/loop-scout-totally-fabricated.md`,
zero premises, a deliberately false claim in the body, written during this
review) was silently absorbed — the legacy count went 6 → 7, nothing else
changed, exit 0.

**Attack B — a file that isn't even shaped like a brief:**
Second file, `not-even-a-valid-filename-shape.md` — no `Branch:`/`Track:`
lines, no `## Premises`, a filename that doesn't match
`loop-<track>-<slug>.md` at all. Legacy count went 7 → 8. Still exit 0,
still `ok`.

**Attack C — the sharper test the brief asked for: make a *current* brief pass as legacy.**
I copied the round's own real brief
(`docket/briefs/loop-meta-briefs-and-premises.md`), renamed its branch to a
fake slug, and **deleted its entire `## Premises` section** — exactly the
shape that fails loudly (correctly) when filed at the top level of
`docket/briefs/`. Placed under `legacy/` instead:
```
$ node D:/AddictedtoAI/scripts/check-briefs.mjs
docket/briefs/ check -- 1 current brief(s), 9 legacy brief(s) (exempt, see docket/briefs/README.md)
...
ok    all current briefs declare their premises
EXIT:0
```
A brief with **zero** sourced premises passes cleanly, purely by virtue of
which directory it sits in.

All three test files were removed and `git status --short` confirmed empty
before continuing.

**Verdict on this question: the exemption is pinned to nothing.** It is a
directory anyone — any future round, careless or adversarial — can drop
anything into, with no filename check, no date check, no provenance check,
and no allowlist of the six files it was created for. This is the same
shape CHARTER's own history already flagged: round 170's `KNOWN_FAILURES`
keyed an exemption on a coarse identifier (route name) rather than pinning
it to the specific content it was meant to excuse, and a reviewer
demonstrated live that a different, worse failure on the same route was
silently absorbed. `legacy/` repeats that shape at the directory level
instead of a list level. The fix is cheap — an explicit, checked-in
allowlist of the six legacy filenames (or any provenance check that a
`legacy/` file isn't new in the diff) — but nothing like it exists today.
This is why I'm requesting changes: it is the round's own headline concern,
I reproduced it three independent ways, and it undermines the property the
round exists to establish (every brief's premises are checkable going
forward) for exactly the population of files — new legacy/ additions —
that a careless or dishonest round would use to dodge the requirement.
