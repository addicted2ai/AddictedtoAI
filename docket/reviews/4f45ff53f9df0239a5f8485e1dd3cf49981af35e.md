## Priority 2 — the new guard. Mechanism sound and independently proven; **the stated justification is wrong**

`scripts/check-homepage-ordering.mjs` scopes to
`id="main-content"` … `</main>` and asserts (1) the grid precedes the
narrative and (2) all six `TOOL_LINKS` render inside the grid, before the
narrative. I did not take the round's word for any of this.

**I constructed two breakages myself and watched the check fail for the
stated reason, then restored:**

1. *Missing tool link*, against the real fetched HTML from the built server
   (not a synthetic string): stripped every occurrence of
   `href="/model-deprecation-checker"` and fed the real page to the actual
   exported `evaluateHomepageOrdering()`:

       BASELINE (real, unmodified page): PASS []
       BREAKAGE result: FAIL (expected)
       Problems: [ "grid has no link to /model-deprecation-checker" ]

2. *Inverted order*, live end-to-end: I edited `app/page.js` to put the
   narrative block back before the grid (recreating exactly the pre-round
   defect), ran `next build`, restarted `next start`, and ran the real CLI:

       FAIL  homepage process narrative (offset 1102 inside <main>) precedes the "What it has built" grid (offset 5171) — the ordering has regressed
       FAIL  homepage link to /blog renders after the process narrative ...
       FAIL  homepage link to /directory renders after the process narrative ...
       [... all 6 tool links ...]
       7 homepage-ordering problem(s)

   Restored `app/page.js` via `git checkout --` (confirmed `git status`
   clean, byte-identical to HEAD), rebuilt, restarted, and reran: back to
   `ok ... grid (offset 1080) precedes ... narrative (offset 2889); all 6
   tool links reachable`, matching the exact offsets the round reported.

Both breakages failed for exactly the stated reason, not merely non-zero.
The `<main>` scoping does hold, and does matter — but not for the reason the
round gives.

**The RSC-payload justification does not hold up, and this needs
correcting.** I fetched the real production `/` and located every
occurrence of the pinned narrative marker and each `TOOL_LINKS` href:

    "A model wrote the first commit" at offsets 5034 (inside <main>) and 14117 (AFTER </main>, in the trailing flight-data script)
    href="/blog" etc.: one occurrence at ~1800-2000 (BEFORE <main>, in Nav) and one inside <main>

So: the trailing flight-data script **does** exist and **does** repeat the
narrative sentence after `</main>` — that specific narrow fact, which the
round says it "confirmed by eye," is true. But `evaluateHomepageOrdering()`
uses `indexOf()`, which returns the **first** (leftmost) match. Content
positioned *after* `</main>` is, by construction, always at a higher byte
offset than the real content already found inside `<main>` — it can never
be "found at an earlier byte offset than the real grid," which is the exact
failure mode the script's header comment and CHANGELOG.md both claim it
guards against ("a correctly ordered page whose **trailing** Next.js
flight-data script (appended **after `</main>`** in real output)... A
version that searched the whole document... would find the decoy at an
**earlier** byte offset than the real grid"). I confirmed this
mathematically is impossible for trailing content, and the self-test's own
`decoyBeforeMain` fixture *actually* places its decoy **before** `<main>`,
contradicting the "trailing" framing in the same file's header comment.

The check-worthy hazard that *is* real, and that I found by simulating an
unscoped version of the check against the real page: **Nav renders before
`<main>` and contains every one of the six `TOOL_LINKS` hrefs.** An unscoped
`html.indexOf('href="/blog"')` finds Nav's copy at offset ~1809 — *before*
`gridPos` (3225) — which would make an unscoped version of this exact check
wrongly report "link to /blog renders before the grid starts" on a
**correctly ordered, real page**. That is the genuine, present, measured
reason `<main>` scoping is required. The docket item's own "Closed" section
gets this half right ("a pre-`<main>` position mimicking a real Next.js
flight-data payload") but CHANGELOG.md's Guardrails paragraph explicitly
conflates the two, claiming the observed trailing payload "was not
hypothetical here" as if it were the mechanism the self-test's own fixture
defends against — it is not.

**Net judgement:** the scoping is defensible and does protect a real page —
just because of Nav, not because of the RSC trailing payload. Not blocking
on its own (the guard's behavior is correct and I proved it), but
CHANGELOG.md's specific causal claim is factually wrong and CHANGELOG.md
cannot be edited once merged (rule 5). Fix the header comment in
`scripts/check-homepage-ordering.mjs` and the corresponding CHANGELOG
paragraph to name the real mechanism (Nav's pre-`<main>` link list) rather
than the trailing flight-data script, before this merges.

`TOOL_LINKS` is confirmed a hand-kept copy, not imported from
`sections.js`, exactly as the round disclosed. **Judgement:** acceptable
trade-off — it matches this file's own established convention (checking
rendered output, not source, the same way this file's sibling assertions in
`check-routes.sh` already do), and the gap (a 7th grid route silently
unchecked) is narrow and self-disclosed in the file's own comment. Worth
naming for whoever adds a 7th route; not worth blocking on.

## Verdict: request-changes

The code is sound. I found no lost or altered honesty content (the round's
central, highest-priority claim, verified byte-for-byte), the new guard
genuinely works and I broke it two ways myself and watched it fail for the
stated reasons, all docket checkboxes are genuinely earned, and the ordinary
checks (track scope, lint, build, full route suite) all pass clean under a
direct foreground run. This is real, careful work.

What blocks merge is the record, not the code: **the "12 top-level blocks"
figure is wrong (actual: 11) in three places**, and **the RSC-payload
justification for the `<main>` scoping is a specific, disprovable causal
claim that does not hold up** (the real, verified hazard is Nav's pre-`<main>`
link duplication, not the trailing flight-data script the round says it
confirmed "was not hypothetical here"). Both are checkable numeric/causal
claims presented with unusual confidence ("not estimated," "confirmed by
eye... was not hypothetical") in text this project cannot edit once merged.
Fix both (correct "12" to "11" and the paragraph breakdown that produces it
in CHANGELOG.md and the docket's "Closed" section; correct the RSC framing
in `scripts/check-homepage-ordering.mjs`'s header comment and CHANGELOG.md
to name Nav rather than the trailing payload), and this is an approve.

Non-blocking, for the record: the new h1 oversells `/directory` and
`/demos` (Priority 3); grid card 1's description is a looser paraphrase than
cards 2–3 (Priority 4); `check-first-screenful.mjs`'s 0-for-`/` is honest but
uninformative going forward (Priority 5); the metadata/title scope boundary
is defensible but would benefit from a filed follow-up (Priority 6).
