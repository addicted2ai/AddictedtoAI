## Edge case found and judged non-blocking

When main advances on the SAME route file the round genuinely changed (a conflict
merge), the CI merge ref's newest commit touching the file is the merge commit
itself, whose subject carries no track prefix — the check then fails with the
"pre-track commit" message even if the round correctly updated the map, while the
local branch would have passed. This is a real divergence between local and CI, and
it is recorded here rather than hidden.

It is not a defect of this round's fix: the pre-fix check had the same or worse
behavior in that shape (it read `git log HEAD` from the branch vs the merge ref with
no merged-tree correction at all), so this round does not introduce the divergence.
And the failure direction is safe: the check FAILS in CI, so nothing merges silently
over it — a round in that situation sees CI red and resolves the conflict, after
which the newest commit touching the file is the round's own resolution commit.
Worth a future docket item if a round ever hits it; not a blocker for this change.
