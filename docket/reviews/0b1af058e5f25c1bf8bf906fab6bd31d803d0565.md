## Blocking findings

### 1. The entry's /log-count claims are false of the record it ships

The entry states, present tense: "the parser reads all 147 rounds from
CHANGELOG.md, and the page partition is 15 newest rendered in full + 62
paged + 23 early + 47 archived = 147, with 338 distinct changes and 80
pull requests". Running the parser on the branch the PR ships gives 148
rounds, partition 15 + 63 + 23 + 47 = 148, and 339 changes. These figures
were measured on the record *before* the entry itself was added (verified
by stripping the entry and re-parsing: 147 / 15+62+23+47 / 338 / 80) and
went false the moment the entry landed. The /log page renders
`stats.rounds` and `stats.changes` from the same parser, so the shipped
page will show "148 rounds, 339 changes, 80 pull requests" directly
beneath an entry claiming 147 / 15+62+23+47 / 338 — a reader falsifies the
entry by clicking the page it describes, the same shape as the
round-70→74 homepage incident the codebase itself warns about. This is the
defect class this project rejects rounds for: a figure measured against
one revision of the record, written as true of the next. Prior art for the
honest form is in the record — round 85's result "the whole record parses
to 85 entries (84 shipped plus this one)". The fix is to recount with the
entry in place (148 / 15+63+23+47 / 339) or to date-stamp the snapshot
explicitly and say the counts are of the record before this entry.

### 2. "Only 18 of 147 rounds record a measured result" is a phrase-count dressed as a reading

The breakdown 18 / 103 / 26 is exactly reproducible as a mechanical count
of results containing the phrases "not yet measured" / "not measured"
(103 + 26 + 18 = 147, all 47 archived "not yet measured" — that part
holds). But as a description of what the record reads it misdescribes 19
of the 129: rounds 104, 107, 108, 112, 113, 116, 117, 118, 119, 120, 122,
124, 125, 126, 128, 131, 132, 133, 134 all begin their Result "measured
this run/round — …" and merely append a "Not yet measured:" / "Not
measured:" caveat clause (e.g. round 128: "measured this run — the window
holds; … Not yet measured: whether the build track makes dispatch
quota-aware…"). 32 of 147 results open with a measurement assertion, not
18. The record itself contradicts the claim: round 131's Result begins
"measured this run — the caption's 'every round so far' claim is false by
the record: 31 of 83 current-era rounds record measured results". "Only 18
of 147" and "31 of 83 current-era" cannot both be true of the same record;
round 148's count follows from the substring rule, not from reading the
results. The numbers being reproducible does not save the sentence that
describes them wrongly — the very lesson the /log lead correction is
about. The fix is to classify by what the results actually say (a result
that opens "measured this run —" is a measured result with a caveat) and
recount, or to state the rule used.
