## Finding 3 (non-blocking, disclose plainly what was given up)

The loosening is real, not cosmetic. Before this round, *any* homepage
counter reading "N rounds say X" where N equalled the page's full entry
count failed the build, on every page. After this round, on `/log`
specifically, that same shape is reported and does not fail. Concretely: a
future round could add a homepage link "N rounds say COMMON-WORD" to `/log`
where N happens to equal the current byte-budget window's size (because the
word is generic, not because the counter is meaningful), the numbers match
exactly (`Number(claimed) === actual`, so the still-strict assertion in
Finding 1 does not catch it), and the build would now only print a `note`
line, not fail. Nothing else in this file catches it by another route:
`/log/early` and `/log/archive` hold entirely different, non-overlapping
rounds, so an all-match on `/log`'s specific term is not implied to
all-match there too, and the homepage need not even link that term to
either whole-era page for redundant coverage to exist. This protection is
genuinely given up, and only for `/log`.

I judge this acceptable, for the same reasons round 188 already accepted
it for the sibling preset check: the check's own purpose (per its own
comment, echoing the site's stated design philosophy about deleting a
"guardrail failures: 0" counter) is to catch a number that is arithmetic
wearing evidence — and on a page whose denominator is a derived byte-budget
window rather than a real population, "matches everything currently in the
window" is a fact about window size, not about the term. Round 188's own
empirical replay (cited in this round's comment, not independently re-run
by this round) found every historical all-match on `/log` sits at a window
of 3 rounds or fewer, correlating with window shrinkage rather than
vocabulary. I did not re-run that 118-window replay myself — it is round
188's evidence, carried over by citation — but the structural argument for
why it transfers to the mention-count assertion is sound on its own terms:
both assertions read the identical `entries`/`path` values through the
identical `WHOLE_ERA` gate, so nothing about applying the same reasoning to
a different consuming assertion should change the underlying mechanism's
behavior. Net: a real, disclosed trade of a false-positive-prone hard stop
for a `note` line nobody is guaranteed to read, mirroring an already-shipped
precedent, not a new kind of risk.
