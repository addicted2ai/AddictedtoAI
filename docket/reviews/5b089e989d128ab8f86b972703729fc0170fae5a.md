# Findings

### F1 — both documents assert they do not type the count, and then type it

`AGENTS.md:34` says "The count is deliberately not typed here" and `AGENTS.md:36`
says "while the charter had 22". `every-run.md:9` says "The count is not typed
here on purpose" and `every-run.md:11` says "the charter had 22". The changelog's
"Change: neither types a count now" is, read literally against the tree, false.

Mitigating: the digit appears only in a past-tense correction clause that rule 5
requires, and "the charter had 22" stays true forever regardless of what the
charter becomes — so it cannot drift stale, and nothing needs to guard it. The
charitable reading of "typed here" is "asserted here as the authority", which is
accurate. But this is the exact class of imprecision the round exists to
eliminate, in the round's own prose, and a reader skimming `AGENTS.md:36` can
carry "22" forward as the live count — which is how "21 rules" propagated in the
first place.

### F2 — an absolute about `ship` that overshoots by one case

`every-run.md:127–128`: "`scripts/round.mjs ship`, which decides whether to arm
auto-merge from your entry's `Origin` and not from the paths you touched". The
registry `why` string puts it more strongly still: "withholds auto-merge by
Origin and never by path".

`ship` does have exactly one path test. `round.mjs:509–517` withholds auto-merge
and exits 1 when the branch changes no `CHANGELOG.md`:

```js
const logChanged = tryRun("git", ["diff", "--name-only", "origin/main...HEAD", "--", "CHANGELOG.md"]);
if (!logChanged.ok || !logChanged.out.trim()) {
  bad("this branch changes no changelog entry — auto-merge withheld");
```

The substantive claim — that the `human-owned-paths` *set* is not what `ship`
consults — is true and a large improvement on what it replaced. The absolute is
one counterexample too broad, forty lines above the line the changelog cites.

Same paragraph, milder instance: "Two separate things can hold a change back"
reads as exhaustive to a fresh reader, though any failing required check or an
active `docket/HOLD.md` also holds a change back. In context it is clearly
scoped to the two mechanisms the old paragraph conflated.

### F3 — the gap is closed in a sibling script, not in the file that has it

The canary lives in `check-governance-claims.mjs`. `check-frame.mjs` itself is
unchanged, so `node scripts/check-frame.mjs` — the exact command `CLAUDE.md`,
`FRAME.md`'s own maintenance section, and the maintainer's global rule all
direct a reader to run — still exits 0 printing `verified 14. CHARTER.md has
999 rules`, as reproduced in section 2.

CI is covered: `check-routes.sh:345` and `:389` run both scripts inside
`build-and-audit`, so a stale heading is a red pull request. The residual is the
documented *human* verification path, whose whole promise is "run this command
yourself rather than trust this file". Worth a follow-up in `check-frame.mjs`.

branch-protection required list", and `automerge-origin.mjs:42–44` states "the

which `check-frame.mjs` verified live against the GitHub API this session, gives

Not introduced by this round and not quoted into the new prose — the round

### F5 — the sweep half would have caught one of the three defects

Running the eleven tripwires over the base revisions of both files gives exactly

### F6 — `README.md` still carries three false claims (correctly out of scope)

means editing a `human-owned-paths` file and spending the grant in the same pull
