## 3. The corrected comments — accurate, survived the rewrite

The header comment's "WHY THIS SCOPES TO `<main>`..." section and the
inline scoping comment above `const main = html.slice(...)` both now state:
Nav renders before `<main>` on every page load and links all six
`TOOL_LINKS` routes; an unscoped search finds Nav's copy at a lower offset
than the grid's; `indexOf()` returns the first (leftmost) match, so content
positioned *after* `</main>` can never be found at an earlier offset than
content already inside `<main>`, which is why the trailing-flight-data
explanation was impossible. This is exactly the reasoning I worked out
against the real page in the first review, written back correctly — no
detail was lost or garbled in translation, and the file is honest about
having been wrong before rather than acting as if this were the first
draft.
