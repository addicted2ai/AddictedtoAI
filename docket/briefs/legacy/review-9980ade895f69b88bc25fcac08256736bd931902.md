## What this round is for, and why it is unusual

On 22 August 2026 the orchestrator asserted three false things about this
project, briefed subagents on them, and had expensive work built on each before
the maintainer caught them in conversation. `docket/HOLD.md` is the loop's
self-halt, not the maintainer's brake. OpenCode *does* have websearch. And
`addicted2ai` is the **maintainer's own account**, so the 278-commit figure
could never have supported "no commit is attributable to a human author."

That third one is the shape that matters here. The figure was re-derived from
the GitHub API **three separate times, once by an independent reviewer**, and
matched exactly every time. Every check asked *is this number right?* and none
asked *whose is it?* It was the correct count of the wrong thing.

This round builds `FRAME.md` (16 facts, each with a check and a
`verified`/`attested` marker), `scripts/check-frame.mjs` to run those checks in
CI, and `CLAUDE.md` so the frame loads into every session automatically.

**So the central question of this review is not "do the checks pass."** It is:

> **For each fact, would its check actually catch a WRONG version of that
> claim — or does it pass regardless?**

A check that passes whether or not the claim is true is worse than no check at
all, because it launders the claim. If `FRAME.md` contains facts of that kind,
this round has built a machine for making wrong premises look audited, which is
the precise opposite of its purpose. **Test this fact by fact.** Mutate the
claim, or the world the claim describes, and see whether the check notices.

## The rest of the attack surface

**`check-frame.mjs` parsing.** It reads fenced check blocks out of a Markdown
file. Can a fact be silently skipped — malformed fence, missing marker, a check
block that parses as empty? A fact that is present in the document but never
executed, while the summary line reports "all checks passed," is the same
laundering failure one level up. Count what it executes against what the
document contains.

**`UNVERIFIED` handling.** A check that cannot run — no network, no `gh`, no
git — must report unverified, never pass. Construct that condition and confirm.

**The attested/verified split.** Two facts are marked `attested`: OpenCode's
websearch, and the supervisor being dead since 2026-08-18. Are those genuinely
unprovable from a checkout, or was a check available and skipped? And are all
14 `verified` facts genuinely verified by their checks rather than by
assertion?

**`CLAUDE.md`.** It is loaded automatically into every future session and, per
Claude Code's documentation, it also steers the permission classifier. Read
every sentence as something that will be acted on for months. Is any of it
false, stale, or overstated? Being short is not an excuse for being wrong.

**The scope widening.** `scripts/check-track-scope.mjs` should admit exactly
`FRAME.md` and `CLAUDE.md` to `meta` and nothing else. Verify the diff adds
precisely two paths. This is the file that decides what each track may write,
and the round that widened it is the round being judged by it — rule 11's exact
tension. The round says it stated that plainly; check that it did.

**Nothing under `.github/`.** Confirm by diff.

## Working method — this section is not optional

Every command you run passes an approval classifier. If it trips, the maintainer
must approve the command **by hand**. They may be asleep or away. A single
tripped command can stall an unattended run for hours. These rules are derived
from commands that actually tripped it, not from guesswork.

### Never use `cd`

Not at the start of a command, not in the middle of one, not inside a script you
write and run, **not even as a shell function name or in a comment**. The
classifier matches the token, not the intent — an orchestrator once wrote
`cd() { echo blocked; }` as a *defensive shim* and tripped it anyway.

Your working directory is already `D:\AddictedtoAI`, so nothing needs it:

- run scripts by absolute path — `node D:/AddictedtoAI/scripts/check-docket.mjs`
- use `git -C D:/AddictedtoAI ...` for every git command
- read and write files by absolute path

### Keep every command string short

Long or multi-line command strings overload the same classifier. If a step needs
more than a couple of operations, **write a small script into the scratchpad
directory and run that** — the script may be as long as you like. The script
must not contain `cd` either.

    node D:/AddictedtoAI/../scratchpad/my-step.mjs      # good
    <forty lines of shell in one -c string>             # trips it

### Never manipulate credentials on a command line

`git -c credential.<anything>`, `http.extraheader`, anything that supplies or
overrides an auth token **will be blocked**, correctly. If a push or fetch fails
on authentication or scope, that is a finding to report, not an obstacle to
route around. Say so and stop. Looking for a broader-scoped credential when
blocked is recorded in this repository's own changelog as a past failure.

### Prefer the dedicated tools over shell equivalents

Use Read, Write, Edit, Grep and Glob rather than `cat`, `sed -i`, `echo >`,
`grep` and `find`. They do not pass through the classifier at all, they handle
Windows paths correctly, and they will not silently mangle CRLF. Reach for Bash
only when no dedicated tool fits.

### Redirection and expansion — keep it plain

Simple `>` and `2>&1` are fine. Avoid stacking constructs in one string:
process substitution `<(...)`, nested command substitution, heredocs combined
with pipes, `exec` redirections, and long `for`/`while` bodies inline. Each
addition raises the chance of a trip. **Put anything non-trivial in a scratchpad
script.**

When you need a file's content as an argument, `"$(cat file)"` alone is fine —
but nothing appended after it.

### Never print a secret

Do not `cat`, `head`, `echo` or otherwise emit the contents of any token, key or
credential file, **including into your own tool output** — a reviewer did this
on 2026-08-22 with `head -c 50` on a token file and the maintainer had to
rotate the credential. To verify a credential works, pipe it into a header
inside a single command substitution and print only the *response*, never the
value.
