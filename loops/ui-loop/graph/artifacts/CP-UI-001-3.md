# CP-UI-001-3 — Proof Rail

```yaml
id: CP-UI-001-3
version: 1
schema: loops/ui-loop/graph/schemas.md#concept-packet
depends_on: [BRIEF-UI-001.v1]
name: Proof Rail
core_idea: >-
  A different route to K10: the allure is what became possible, not who leads. /frontier leads
  with the merged capabilities rail (deltas, executed tutorials, anchored notes) at large type,
  each item a dated pair with its elapsed-time bracket; leaders and lead changes are demoted to a
  trailing ledger. The impossible/routine pair block, already the site's most human element,
  becomes the signature motif on every template: two inks, two dates, one bracket.
reader_walks_away_with: I saw, dated and sourced, how many things that were research became something I could buy, and how fast.
surfaces: [/, /frontier (new), /impossible-routine, /wiki/<entry>, /tutorials, /catalog]
elements:
  - name: proof rail (lead)
    purpose: read what became true, newest first, typed by proof kind
    data_source: content/deltas/*.md, content/tutorials/*.md, content/blog/*.md, lib/deltas.mjs
    empty_state: rail heading + criterion line + "nothing dated in this window"
    provenance_label: kind word (became routine / proven by execution / reported), date, source link at each end
  - name: elapsed bracket
    purpose: read the interval from first result to purchasable in one glance
    data_source: content/deltas/*.md (impossible.date, routine.date)
    empty_state: bracket absent when a pair lacks either date (schema forbids, so absent means no pair)
    provenance_label: n/a (derived from two sourced dates shown beside it)
  - name: leaders ledger (trailing)
    purpose: who leads each published index today
    data_source: data/sources/openrouter-models/latest.json, data/sources/registry.json
    empty_state: ledger heading + "no index published for this window"; the page stands on the rail
    provenance_label: "index · <publisher> · read <date>"
  - name: lead-change lines
    purpose: when a lead last passed, and by arrival or rescoring
    data_source: data/changes.jsonl
    empty_state: "no lead change recorded yet"
    provenance_label: snapshot date + feed id
  - name: vendor claim aside
    purpose: the vendor's own figure, set apart from index and proof
    data_source: content/wiki/model/*.md (cited facts, when present)
    empty_state: aside heading + "no vendor claim on file"
    provenance_label: 'tag "claimed · unverified", source, accessed date'
  - name: entry timeline-first
    purpose: on a prose entry, meet the subject, then its dated events, then facts
    data_source: content/wiki/**/*.md (timeline, facts)
    empty_state: timeline block omitted when empty; facts follow the lede directly
    provenance_label: source + accessed per event and fact, as today
  - name: catalog@390 field chooser
    purpose: pick which fields show; 396 rows stay one line each
    data_source: data/derived/catalog.json
    empty_state: existing CatalogFilter empty state
    provenance_label: read date available as a choosable field
design_moves:
  type: Charter stack kept; pair dates at --step-3, bracket label in mono small caps; rail headings in mono tracking
  colour: two inks - --ember for the impossible end, --accent for the routine end - and nothing else coloured; paper otherwise
  layout: rail items are two-column pairs at >=48rem, stacked with the bracket between at narrower widths; leaders ledger uses the existing list-row shape
  motion: none
reuses:
  - {surface: /frontier, nearest_existing: lib/render/delta.mjs pair block + home.mjs rail, differs: new module joining three content kinds into one rail; leaders reuse browse-row}
  - {surface: /impossible-routine, nearest_existing: lib/render/delta.mjs, differs: type scale and two-ink rule only}
  - {surface: /wiki/<entry>, nearest_existing: lib/render/entry.mjs, differs: order becomes lede, timeline, facts (F-K12); facts span the measure, S18 column retired}
  - {surface: /catalog, nearest_existing: catalog.mjs + CatalogFilter.tsx, differs: below 34rem, a checkbox field chooser (CSS :has) hides columns; default shows name, in, out, status on one line}
  - {surface: /, nearest_existing: home.mjs, differs: Frontier door shows the newest three proofs}
fence:
  a11y: field chooser is a labelled fieldset of checkboxes; colour never the only carrier (kind word always present)
  reflow_320: pairs stack; single-line catalog rows truncate with title attribute, no overflow
  payload: zero new JS; :has() CSS only, with checked-by-default fallback
  digit_free_fixed_copy: rail and ledger inside [data-derived]; criterion line has no digits
  no_external_origins: none added
known_risks:
  - rail fills at editorial rate; on day one it holds only the current corpus of pairs, tutorials and anchored notes
  - demoting leaders may fail R-B's reading of the flagship as a players board
  - :has() absent in older engines degrades to all columns shown (reflow still holds)
open_questions:
  - "keeper: R-B names a running board of players; this concept makes it a trailing ledger - accept or rule"
  - "keeper: R7 measure-list cap on the ledger rows keeps pairs and rows at different widths; propose one shared measure per template"
  - "measure: do readers find a model faster on a one-line-per-row catalog than on today's stacked records"
build_estimate:
  files: [app/globals.css, lib/render/delta.mjs, lib/render/entry.mjs, lib/render/catalog.mjs, lib/render/home.mjs, app/_components/CatalogFilter.tsx, app/page.tsx]
  new_files: [lib/render/frontier.mjs, app/frontier/page.tsx]
```

The bet is that proof beats ranking: a dated pair with sources at both ends is the most persuasive object this site owns.
