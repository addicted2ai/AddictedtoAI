# Iteration 9 — work queue: apply F16 across the board

**Two judges scored iteration 8 independently and returned an IDENTICAL 8.40**, with nine of
eleven categories scored the same. They also, unprompted, named the SAME dominant failure
mode — and every item below is an instance of it.

## The failure mode you are fixing

**A check registered to close an item inherits the ITEM's scope, not the RULE's.** An item
names a defect on the surface where someone noticed it. The fix lands there, a check is
written that passes there, and the check is filed against the governing RULE. From then on
the rule is believed enforced — while every other surface it governs stays untested and
often still broken, under a green gate.

**This is now the loop's dominant residual defect class.** All six items below are the same
shape. Fixing them one surface at a time recreates the problem; fix the SCOPE.

## What that means concretely for every check you touch

1. State the **rule's full domain** — every surface the rule governs, not the ones its
   originating item mentioned.
2. Assert across **all** of them.
3. Make the check's `intent` name its coverage explicitly, so a narrower implementation
   reads as a contradiction rather than as silence.
4. Where the rule genuinely governs only one surface, say so in `intent` and why.

**Two live examples of the trap from the judges:** S20's intent claims a page-wide accent
prohibition and reads only `.door`/`.delta`; S19 asserts alignment *within* a category while
R13's property is page-wide, and `/tools` lands seven distinct x positions across twelve
categories.

## Standing requirements

- The registry refuses any invariant without falsifier evidence in BOTH directions, or a
  real `oneSidedBecause` argument about the property. **One such declaration exists (S20)
  and judge B considers it insufficient given the scope defect — re-examine it.**
- Verify each item's checkable specifics against source before building. A fabricated field
  name once propagated from a verdict into source comments.
- Falsify with `--only <id> --break "<css>"` (~3s), not rebuilds (~106s). Batch breaks; full
  gate once at the end. An intermittent falsifier is a FINDING, not a flake.
- Content is READ-ONLY.
