## Verdict: revise

Two changes are required. Neither is large; both are the difference between a
sweep and a partial sweep that says it was a sweep.

**1. `content/wiki/model/openai-gpt-5-4.md:55-56` is an unfixed instance of
exactly the defect this job exists to remove.** The prose reads:

```
5.2 and 5.3-Codex all cap at {{fact:model/openai-gpt-5#context_window}}
tokens. This row broke the plateau —
```

The transclusion ends line 55; the literal `tokens.` opens line 56. The job's
stated pattern — "a `context_window}}` transclusion followed by a
word-boundary 'tokens'" — is a *same-line* grep, so every line-wrapped
occurrence was outside the search from the start. This one is not listed in
the drop record's "judged not a doubling" section either, so it is not a
judgment call that went the other way; it was never seen.

Measured, not inferred. `lib/units.mjs` maps
`openrouter-models|context_length` → `tokens`; `content/wiki/model/openai-gpt-5.md:23-26`
declares `context_window` as `source: feed`, `feed: openrouter-models`,
`path: context_length`. Rendering that fact through the real renderer
(`renderFact(..., { inline: true })` against `data/derived`, tags stripped,
source element removed):

```
model/openai-gpt-5#context_window
  renders as: "400000 tokens"
```

So the built page reads "all cap at **400000 tokens** tokens. This row broke
the plateau" — the same sentence shape as the three the job did fix.

**2. The drop record's "Rendering before → after" table contains a figure the
renderer does not produce.** It gives, for `openai-gpt-5-6-luna.md:83`:

> "runs 200000 tokens **tokens** against Nano's" → "runs 200000 tokens against Nano's"

Luna's context window is not 200000. Same measurement run:

```
model/anthropic-claude-haiku-4-5#context_window  renders as: "200000 tokens"
model/anthropic-claude-opus-4-5#context_window   renders as: "200000 tokens"
model/openai-gpt-5-6-luna#context_window         renders as: "1050000 tokens"
model/anthropic-claude-opus-5#price_output       renders as: "0.000025 USD per token"
```

`data/changes.jsonl` agrees: the Luna rows that arrived 2026-09-01 carry
`"context_length":1050000`. The 200000 appears to have been copied from the
proposal's own quote rather than read off a rendered page — which is what
makes it a reason and not a nit, because that table is the job's evidence
that it rebuilt and checked each affected page. Three of its four rows are
right; the fourth was not measured. Fix the figure (and, if the rebuild was
in fact run, the row is easy to re-read from it).

## What I checked, and what came back clean

- **The four edits are correct.** Each deleted literal sat immediately after
  a fact that genuinely renders its unit: `haiku-4-5#context_window`,
  `opus-4-5#context_window` and `gpt-5-6-luna#context_window` all resolve to
  `feed`/`openrouter-models`/`context_length` → unit `tokens`, and
  `opus-5#price_output` → `pricing.completion` → `USD per token`. The
  `anthropic.md` case is the subtler one and the author got it right: "at
  {{price_input}} and {{price_output}} per token" rendered the unit twice on
  the second fact, and dropping the trailing literal leaves both figures
  still carrying "USD per token" from the renderer.
- **Coverage of everything else.** I ran my own sweep rather than trusting
  the record's: parse every entry's `facts:` block into `<entry>#<field>` →
  unit using `lib/units.mjs`'s `FEED_UNITS`, then scan every transclusion in
  `content/` with the *following 60 characters read across newlines*. Result:

```
transclusions of unit-carrying facts: 152  (unresolvable targets skipped: 0)

content/wiki/model/openai-gpt-5-4.md [tokens] ... tokens. This row broke the plateau — {{fact:model/openai-gp
suspect count: 1
```

  Instrument ruled out before concluding: `grep -ro "{{fact:[^}]*}}" content`
  counts **368** transclusions and **0** containing a `|`, so the regex that
  produced the 152 matched every transclusion in the corpus, not a subset —
  and no target failed to resolve. Beyond the one above, nothing follows a
  unit-carrying transclusion with `tokens`, `per`, `USD`, `Mtok`, `/token` or
  `dollars`.
- **The drop record's other coverage claims hold.** Non-wiki surfaces:
  `grep -rn "{{fact:" content --include=*.md -l | grep -v content/wiki/`
  returns exactly `learn/open-weights-and-closed-models.md` and
  `learn/what-a-benchmark-measures.md`, and both transclude *cited* facts

  `unitFor()` returns null for anything whose `source !== 'feed'`, so no unit
  renders and no literal after them could double. No tutorial, blog or
  directory file carries a transclusion at all.
- **The "judged not a doubling" list.** I read each of the seven and agree
  with all seven: `context window` / `of context` after a figure is the noun
  the quantity modifies, not a repeated unit, and the brief blesses that
  reading explicitly. `x-ai-grok-4-6.md:110`'s "input" after a price fact is
  a side label, not a unit. See the `carry:` entry for a readability nit on

- **Scope.** The diff touches four content files (one word each), adds the
  drop record the brief asked for, and adds `.job/`. No reserved path, no
  machinery, no data edit, no second proposal. That is within the stated
  outcome — scope is not the problem here.
- **Rejection index** is empty; nothing to match against, and this is a
  mechanical defect class rather than a re-tread of an idea.
