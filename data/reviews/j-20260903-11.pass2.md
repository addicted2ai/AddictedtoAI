## The pass 1 finding is an instrument artifact

Pass 1 concluded that `https://deepmind.google/models/gemini/flash/` contains
neither `10.0` nor `8.8`, reporting the Harvey chart's alt text as the
truncated string `Bar chart comparing AI performance on Harvey`.

It contains both, twice, in full. I fetched the page with `node`'s `fetch`
(HTTP 200, 220920 bytes, no redirect) and searched the raw bytes for the alt
sentence. Two occurrences, both on an `<img>`:

```
--- raw occurrence 1 at byte 183512 ---
...=w2880-h1620-n-nu-rw-lo 2880w" type=image/webp><img alt="Bar chart comparing
AI performance on Harvey's Legal Agent Benchmark. Gemini 3.8 Flash leads with
10.0%, followed by Gemini 3.7 Flash (8.8%), Claude Opus 5 (6.7%), Claude Sonnet
5 (5.0%), GPT-5.6 Sol (2.5%), and GPT-5.6 Terra (0.8%)." src="https://lh3.goog...

--- raw occurrence 2 at byte 185614 ---
[identical alt, second image]

total raw occurrences of the alt sentence: 2
```

`10.0%` for 3.8 Flash and `(8.8%)` for 3.7 Flash. The entry's value —
`"10.0%, against 8.8% for Gemini 3.7 Flash"` — is the cited page verbatim.

**The cause is reproducible and worth writing down, because it nearly cost a
correct job.** The two charts on that page use different attribute delimiters,
each forced by its own content:

- Harvey: `alt="... on Harvey's Legal Agent Benchmark. ... 10.0% ..."` —
  double-quoted, because the text contains a literal apostrophe.
- Vals: `alt='A bar chart comparing performance on "Vals Finance Agent v2"
  tasks, showing Gemini 3.8 Flash leading at 61.4%, followed by Gemini 3.7
  Flash (59.0%), ...'` — single-quoted, because the text contains literal
  double quotes.

An extractor matching `alt=["']([^"']*)` recovers the Vals alt whole and cuts
the Harvey alt at the apostrophe in `Harvey's` — producing exactly the string
pass 1 quoted. Pass 1 then read the asymmetry ("the same method recovered the
Vals numbers, so the extractor works, so the Harvey numbers really are absent")
as confirmation. It was the bug's signature, not evidence.

I am not scoring a point here: **my own first extractor had the mirror image of
the same defect.** It matched `alt\s*=\s*"([^"]*)"` — double quotes only — so
it found the Harvey numbers and reported `61.4%` and `59.0%` MISSING:

```
[found   ] deepmind-flash      "54.9%"
[MISSING ] deepmind-flash      "61.4%"
[MISSING ] deepmind-flash      "59.0%"
[found   ] deepmind-flash      "DeepSWE v1.1"
```

Both figures are present; a raw-byte search found them immediately (occurrences
at bytes 178288 and 180403, quoted above). Two reviewers, two complementary
regex bugs, one page. That is what the `proposal:` above is for.
