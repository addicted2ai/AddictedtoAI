## The check I ran myself

The post's last technical claim is a measurement, so I measured it. Script:
create a scratch repo under the OS temp dir, point `GIT_CONFIG_GLOBAL` at a
file containing `[core] fsmonitor = false`, write `fsmonitor =
MARKER-LOCAL-WINS` into the repo's own `.git/config`, and read the value. Only
`git config` is ever invoked in that repo — never `git status` — so nothing
executes. Output:

```
git version: git version 2.40.0.windows.1
global file says: [core] fsmonitor = false
git config --get core.fsmonitor -> MARKER-LOCAL-WINS
git config --show-origin --get core.fsmonitor -> file:.git/config	MARKER-LOCAL-WINS
with only global (no local):
  -> false
```

That reproduces the post's paragraph exactly, including the git version it
names and the `--show-origin` result. The Hacker News's fourth mitigation
really does not do what it says, and the post is right to say so.
