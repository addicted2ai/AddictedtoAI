## `data/launch.json` — the only part of the diff that needed defending

It is not what the repair needed, so I checked whether it is a real gate
artefact or hand-typed numbers. `scripts/verify-design.mjs:576-601` rewrites
the entire `js_payload` block (and `design_verification`) at the end of a run,
via `Number((bytes / 1024).toFixed(1))`. Three things say this file was written
by that code path and not by a person:

- `"inline_kb_gzipped": 18` — `Number((18.0).toFixed(1))` serialises as `18`,
  which is what a script emits and not what someone editing JSON types;
- the totals are measured, not summed (104.4 + 6.3 = 110.7, recorded 110.6),
  and the same non-additivity holds in the previous recorded state
  (104.4 + 6.5 = 110.9, recorded 110.7) — a fabricated block would be
  additive;
- `design_verification` stayed `{date: 2026-09-03, pass: true, failures: 0,
  checks: 46}`, which is consistent with a run today that passed; the same run
  is what moved the payload numbers.

The figures move on pages this diff cannot touch (home html 10 → 9.6, entry
7.8 → 7.6, catalog 34.7 → 34.5), which is at first reading suspicious — but
that is the file's normal behaviour, not a signal: `0011115` (21:30 the same
day) moved catalog 18.3/123.3/34.9 → 18.2/123.1/34.7 for the same reason, each
gate run measuring its own build of its own tree. Repo precedent for committing
it is established (`0011115`, `54a2d57`, `f6b3cb0`), and leaving it uncommitted
is a known hazard — `pulse/lib/publish.mjs:91` records a scheduled Pulse
sweeping an uncommitted `data/launch.json` edit into its own commit
(`addictedtoai-ps3`). So: a mechanical by-product of a mandated gate, recorded
rather than reverted. Not scope creep. The one thing I would have liked is a
commit-message line saying so — `0011115` explained its movement, this one is a
single subject line — but that is a note, not a finding, and the commit is
written.
