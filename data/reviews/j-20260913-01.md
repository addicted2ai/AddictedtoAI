## Required change — state the measured classification without contradicting it

Lines 112–118 say:

> The `inception/mercury-2.5-preview` row left the OpenRouter catalog in the
> 2026-09-09 fetch, eight days after it arrived, and none of the usual reasons
> apply. The model was not retired, no router dropped it, and nothing was folded
> into a service tier. ... What this page describes is being served right now
> under a shorter name.

That wording is not supportable as written. The work source explicitly lists a
rename as one of the possibilities the repair must distinguish. This diff's
own evidence shows the old catalog identifier was removed and a new identifier
appeared: `data/changes.jsonl` records the same hash pair on 2026-09-09 as
`inception/mercury-2.5-preview|$retirement` and
`inception/mercury-2.5|$arrival`. The live OpenRouter page
(`https://openrouter.ai/inception/mercury-2.5-preview`) returns HTTP 307 with
`Location: /inception/mercury-2.5`, while
`https://openrouter.ai/api/v1/models/inception/mercury-2.5-preview-20260831/endpoints`
returns the preview id with `endpoints: []` and
`https://openrouter.ai/api/v1/models/inception/mercury-2.5-preview/endpoints`
returns the production id with one Inception endpoint. Calling this “none of the usual
reasons” and saying “no router dropped it” contradicts the measured row-level
rename/removal. “What this page describes is being served right now under a
shorter name” also reaches beyond what the page later admits at lines 149–156:
the publishers do not establish whether the two listings used the same weights.

Rewrite this opening so it says what the sources actually establish: OpenRouter
removed/redirected the preview row to the production-named row, which is the
rename or graduation case at the catalog level; the old route still points at
the successor; and the sources do not settle weight continuity. Do not claim
that the router did not drop the row. Also change “eight days after it arrived”
to “seven days later” (or explicitly say “the eighth calendar date”), and
replace “same evening” with a timezone-qualified timestamp or “same day”: the
successor's `created: 1788892137` is `2026-09-08T18:28:57Z`, which is
`2026-09-08T12:28:57-06:00` on this machine.

## Other unsupported wording in the same rewrite

1. Lines 125–130 say the models page and platform documentation “carry three
   models between them — Mercury 2.5, Mercury 2 and Mercury Edit 2.” The
    current vendor models page (`https://www.inceptionlabs.ai/models`) also
    presents Mercury Voice and Mercury Router,
   and its supported-model note mentions Mercury 1, 2 and Mercury Edit 2;
    the documentation table (`https://docs.inceptionlabs.ai/get-started/models`)
    lists the three core model rows. The sentence is
   not a defensible description of the two pages as a whole. Narrow it to the
   documentation table, or remove the count and simply report the direct
   checks that neither page offers `mercury-2.5-preview` as a current model id.

2. Lines 149–156 say “everything else the catalog publishes about them
   matches.” The committed 2026-09-08 preview row has
   `hugging_face_id: ""`; the successor row in the current snapshot has
   `hugging_face_id: null`. A direct comparison of the two row objects, while
   excluding the expected id/slug/name/created/link changes, printed one
   difference: `hugging_face_id` blank versus `null`. Narrow the sentence to
   the listed substantive fields (context, output cap, parameters, prices and
   description), rather than making the absolute “everything else” claim.

3. The new 2026-09-08 timeline event combines the vendor release and the
   OpenRouter row creation but assigns only the vendor blog as `source_url`.
    The blog (`https://www.inceptionlabs.ai/blog/introducing-mercury-2-5`)
    supports “Today, we’re releasing Mercury 2.5, our most capable
   production model yet,” but not the feed publisher's row-creation fact. Split
   the event or cite the OpenRouter catalog for that second clause so each
   timeline claim is backed by the document named beside it.

These are all one source-discipline problem: the page has enough independent
vendor and feed-publisher evidence to make a useful, cautious account, but its
summary language is broader than that evidence in several places. Preserve the
explicit sentence that the two publishers do not answer whether the listings
ran the same weights.
