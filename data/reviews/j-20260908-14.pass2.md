The remaining blocking defect is in the new retirement mechanism. The queue
calls `resolvedBlockedPrimaries(root)` from `computeQueue`, while that helper
sets `record.surfaced = true` and writes `data/blocked-primaries.json`. A
direct probe of the helper therefore observed one result on the first call and
zero on the second, with the state file changed to `surfaced: true`:
`{"calls":1,"first":1,"second":0,"record":{"...":"...","surfaced":true}}`.
This makes derived-queue computation stateful, contrary to
`openspec/specs/pulse/spec.md`, “The work queue is derived, never accumulated,”
and the repository's explicit rule that recomputation is a pure function of
recorded state. The added regression currently encodes this side effect by
calling `computeQueue` twice and expecting `1` then `0`.

The same ordering can lose a resolved primary. The helper acknowledges every
resolved record before `computeQueue` sorts and applies `QUEUE_CAP`. A direct
51-record probe printed
`{"returned":51,"queueCap":50,"afterSurfaced":51,"ifCapped":50,"lost":1}`.
Thus a record can be marked surfaced even when its verify item is excluded from
`data/derived/queue.json` by the cap, after which it will never be offered.

Required changes: keep queue derivation read-only and move the acknowledgement
to an explicit Pulse transition after the capped queue has actually been
written (or use an equivalent durable transition that preserves pure
recomputation). Acknowledge only records whose item made the capped queue, and
add direct regressions for repeated unchanged computation and for a resolved
item excluded by the cap. Then run the focused test in the normal dependency
environment.
