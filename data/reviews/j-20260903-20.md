## The check that could have gone red, and did not

A price transclusion is exactly what `lib/price-attribution.mjs` polices, and
its cross-row gate is a build **error** with no debt ratchet. I ran both
detectors on the body before and after:

```
=== BEFORE (cb47c21~1) ===
currency literals: 10
price-attribution hits: 0
cross-row hits: 0

=== AFTER  (worktree) ===
currency literals: 8
price-attribution hits: 0
cross-row hits: 0
```

`findCrossRowComparison` does not fire because both new markers name the *same*
entry, so `ids.size < 2` at price-attribution.mjs:434 and the sentence is never
tested for a listing verb. That is the mechanism, not an accident of wording —
worth stating because a version of this edit that had transcluded the fast row
too would have failed the build.

took its rule breakdown as well:
