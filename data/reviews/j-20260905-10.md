## What I was judging

One outcome: the post's sentence "On Claude Code and Hermes Agent the payload
runs before the workspace-trust prompt is accepted" attributed to nobody, when
the claim about Hermes comes from The Hacker News and both primary sources
(Manifold's own Hermes case study, CVE-2026-71963) put the moment elsewhere.

Hermes out and name the two accounts.

## Source checks — the three quotes the new paragraph asserts

The new paragraph makes three sourced claims. I checked each against the
document it names.

Because WebFetch's extractor is evidence in neither direction, I ran the two
HTML fetches twice: once through WebFetch, and once raw, with a throwaway
script (`node C:/Users/.../Temp/rev-j20260905-10-src.mjs`) that fetches the
page, strips tags, and prints **every** occurrence of "workspace-trust",
"workspace trust" and "Hermes" with 220 characters of context on each side —
counted, not truncated, so absence is measured rather than assumed. Both pages
returned `status 200`. The quotes below are from that raw output.

**1. "The Hacker News groups it with Claude Code at the trust prompt."**
`https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html`,
raw, `workspace-trust` occurrence #1: *"On Claude Code and Hermes Agent, the
payload fires before the workspace-trust prompt is accepted; on Qwen Code,
before the user has authenticated; and on Grok Build, on the first keystroke."*
The two products grouped in one clause, exactly as the post now says, and it is
The Hacker News that groups them.

**2. Manifold's Hermes trigger, quoted in the post as "a user opens a
repository with Hermes and sends their first message".**
`https://www.manifold.security/blog/ai-coding-agents-git-hijack`, raw. The
Hermes Agent section reads: *"Hermes runs git status in the session directory
to gather the repository context. It passes the repository's config through
untouched. The index refreshes, the repository's core.fsmonitor command runs on
the host. The trigger. A user opens a repository with Hermes and sends their
first message, and the payload executes as Hermes gathers that context."* The
post's quote is an exact substring.

**The absence is measured, not assumed.** "workspace-trust" occurs exactly
**5** times in Manifold's page and "workspace trust" **0** times. All five are
accounted for and none is in the Hermes case study: two in the intro/TL;DR
("Open a folder with Claude Code and it runs `git status` before you type
anything. Before the workspace-trust prompt"), one in the Claude Code
`core.fsmonitor` case study (*"the repository's core.fsmonitor command ran on
the host, before the workspace-trust prompt was accepted"* — which is the
sentence the post's retained clause rests on), one in the Claude Code
`ultrareview` case study, and one in the closing section. That is the finding,
and it is now what the diff renders.

**3. CVE-2026-71963 "says the same: 'When a user opens the malicious repository
and sends any message.'"**
Fetched `https://cveawg.mitre.org/api/cve/CVE-2026-71963` — the CVE Services
record, which is the URL the post's source paragraph already cites, not a
scraped mirror — and parsed `containers.cna.descriptions` out of the JSON
rather than reading rendered prose. Verbatim: *"Hermes Agent 0.18.2 through
0.21.0, fixed in commit f6234d0, contains a remote code execution vulnerability
that allows attackers to execute arbitrary OS commands by supplying a malicious
repository with a crafted .git/config that sets core.fsmonitor to an
attacker-controlled command. When a user opens the malicious repository and
sends any message, the agent triggers a git status index refresh which executes
the injected command in the user's process context, exposing the full
environment including configured provider API keys."* The post's quote is an
exact substring. A case-insensitive count of "trust" over the **whole raw
response body** — not the description alone — returns 0, so the record's
silence on a trust prompt is measured, not inferred from a rendering.

So all three attributions hold, and the sentence the post now retains — "On
Claude Code the payload runs before the workspace-trust prompt is accepted" —
is the one Manifold's own Claude Code section states directly, no longer
carrying a second product the primary source does not put there.

## The one thing that could have made the new paragraph overclaim

Manifold's intro and TL;DR do say, generically, that agents run git "before you
type a prompt, before the workspace-trust prompt, before you have even
authenticated" — so a sentence claiming Manifold never connects a trust prompt
to any of this would be false. The post does not claim that. It says
"Manifold's own Hermes **case study** never mentions a trust prompt", which is
precisely the scope the count above measures, and it is true: the phrase
appears five times on that page and not once inside the Hermes section. The
qualifier is doing real work and it is the right qualifier.
