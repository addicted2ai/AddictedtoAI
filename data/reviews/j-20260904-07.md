## The instrument note

The evidence file records that a plain `user-agent`-only fetch returns HTTP
403 (Cloudflare) and that the successful request added `accept-language` and
`cache-control`. This is a claim about what something does, so I tested it
rather than take it on trust:

```
$ node C:/Users/BadBitch/AppData/Local/Temp/rev-j07-403.mjs
UA-only: 200 375911 bytes
no headers at all: 403 9861 bytes
```

It did not reproduce. Sending only the full Chrome `user-agent` — no
`accept-language`, no `cache-control` — returned 200 and the full page; what
returned the 9,861-byte 403 challenge was a fetch sending no headers at all,
under Node's default UA. So the UA alone clears the gate and the two extra
headers were not load-bearing.

This is carried, not blocked, for two reasons. It affects no finding in the
diff — the retrieval the note describes is the one I reproduced in full, twice
— and Cloudflare's gating is IP- and time-dependent, so the author plausibly
did observe the 403 they recorded. The note is unreliable as a general
instrument claim, which is worth fixing, rather than false about this run.
