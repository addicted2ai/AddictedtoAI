## The claim the whole job rests on, measured

The correction asserts three fetches of
`https://openai.com/index/daybreak-for-frontline-defenders/`. That is a claim
about what something does, so I ran it rather than reasoning about it. I wrote
a four-case script (the author's three, plus one case they did not run) and
executed it during this review:

```
no headers at all: HTTP 403, 9861 bytes
full Chrome UA alone: HTTP 200, 376064 bytes
UA + accept-language + cache-control: HTTP 200, 376065 bytes
accept-language + cache-control, no UA: HTTP 403, 9861 bytes
```

The three cases the diff claims reproduce on status, and the 403 body size
matches to the byte (9,861, exactly as written). The 200 sizes are ~40 bytes
above the recorded 376,021/376,069, which is the live page drifting, not a
discrepancy in kind — my own two 200s differ from each other by one byte
seconds apart.

The fourth case is mine and it matters: sending `accept-language` and
`cache-control` **without** a UA still returns 403. So the note's surviving
claim — "of those, only the UA is load-bearing against the Cloudflare
challenge" — is not merely consistent with the measurements, it survives the
obvious way to falsify it. The UA is both sufficient (UA alone → 200) and,
against this header set, necessary (the other two alone → 403). The diff
supports the sufficiency half; I checked the necessity half and it holds.

I deleted my script afterwards; the worktree is unchanged.
