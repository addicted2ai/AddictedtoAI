## The finding, verified against the feed rather than against the page

The carry file (`data/carried/j-20260905-14-carry-1.md`, read from `main` since the repair deletes it) argues the old opener was false against the page's own adjacent paragraph. That is true, but it is an argument from the page's prose to the page's prose, and if both sentences were wrong it would still hold. So I checked the underlying artefact instead — `data/sources/openrouter-models/latest.json`, the committed snapshot, `date: 2026-09-05`, 431 rows, read with a throwaway script rather than by eye:

```
anthropic/claude-opus-4    ctx 200000    prompt 0.000015
anthropic/claude-opus-4.1  ctx 200000    prompt 0.000015
anthropic/claude-opus-4.5  ctx 200000    prompt 0.000005
anthropic/claude-opus-4.6  ctx 1000000   prompt 0.000005
anthropic/claude-opus-4.7  ctx 1000000   prompt 0.000005
anthropic/claude-opus-4.8  ctx 1000000   prompt 0.000005
anthropic/claude-opus-5    ctx 1000000   prompt 0.000005
```

The old opener, "Nothing about the row stayed flat over that stretch", is false against those bytes: the input price is byte-identical on five consecutive rows, which is the one thing that most conspicuously did stay flat. The finding holds independently of the prose that prompted it. The replacement, "Not everything about the row stayed flat over that stretch: what moved was the context window, not the price", is true against the same rows — `context_length` moves 200000 to 1000000 at 4.6 and `pricing.prompt` does not move at all from 4.5 onward.

Every other claim in the repaired paragraph checks out against the same table: 4.5 at 200000; "the same ceiling the line had shipped with since the first Opus 4" (`anthropic/claude-opus-4` is 200000, so the claim reaches back as far as it says it does); 4.6 raising it "at an unchanged price" (0.000005 on both sides); "held there through this row and Opus 5" (4.7, 4.8 and 5 all 1000000).

## The price-attribution caveat, which I did not take on trust

The first paragraph hedges: "Each of those is the top listed provider's rate for its row rather than necessarily Anthropic's own, and the 4.1 row is headed by resellers, so the step down sits between listings rather than being a price Anthropic announced." The snapshot cannot support the second clause — its rows carry `top_provider` as a capability object (`context_length`, `is_moderated`, `max_completion_tokens`) and no provider name anywhere. A claim with no artefact behind it in the repository is exactly the shape this review is for, so I fetched the live per-provider endpoint lists as raw bytes with `node`'s `fetch`, both HTTP 200 on 2026-09-06:

```
anthropic/claude-opus-4.1  Amazon Bedrock 0.000015 | Google (vertex) 0.000015
anthropic/claude-opus-4.5  Claude Platform on AWS | Azure | Google | Amazon Bedrock
                           | Anthropic 0.000005 | Amazon Bedrock eu-west-1 0.0000055
```

The 4.1 row has no Anthropic endpoint at all — only Bedrock and Vertex, both at 0.000015. The 4.5 row does, at 0.000005. So the sentence is not merely hedged, it is precisely right about a real asymmetry: the $15 side of the comparison is resellers only and the $5 side includes Anthropic's own listing, which is why the step down is between listings rather than a price Anthropic announced. This also puts the page in the state `data/price-attribution-debt.json` calls "the state the file is supposed to reach" — the house clause is present and earned rather than pasted.
