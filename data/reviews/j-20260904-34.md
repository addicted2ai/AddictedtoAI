## Whether the substitution is the *correct* one

This is the part worth checking: the fix is only right if `z-ai/glm-5.3-flash`,
and not the pointer row, is the row that carries the four attributes the
sentence attaches to it. Ran the real `deriveStatus` from `pulse/lib/diff.mjs`
against the real 2026-09-04 snapshot (both unchanged on this branch, so the main
checkout's module is the same code — the worktree has no `node_modules`):

```
snapshot date: 2026-09-04
status_rule: {"kind":"expiration_date","path":"expiration_date","deprecated_within_days":365,...}
z-ai/glm-5.3-flash
   expiration_date="2098-12-31" -> deriveStatus=active  ctx=1310720  prompt=0.000000075  completion=0.00000025
~z-ai/glm-flash-latest
   expiration_date=null -> deriveStatus=active  ctx=1310720  prompt=0.000000075  completion=0.00000025
z-ai/glm-4.7-flash
   expiration_date="2026-09-10" -> deriveStatus=deprecated  ctx=202752  prompt=0.00000006  completion=0.0000004
input : 25.0000% dearer  (claim: 25%)
output: 37.5000% cheaper (claim: 37.5%)
```

Every figure the now-named row is credited with holds: `active`,
`expiration_date` "2098-12-31", 1,310,720 context against 202,752, 25.0000%
dearer on input, 37.5000% cheaper on output. The percentages are exact, not
rounded.

The measurement also confirms the ambiguity was real and not a stylistic
complaint. The pointer row genuinely shares two of the three attributes —
identical `context_length` 1310720 and the identical pricing pair — and differs
only on `expiration_date` (null vs "2098-12-31"). A reader resolving the old
pronoun to `~z-ai/glm-flash-latest` would have gotten the context and both
prices right and the sentinel wrong, with no signal. Naming the row is the fix
that removes that, and it is the only one that does.

The parenthetical "the far-future sentinel this site's status rule reads as
active" is supported verbatim by the registry's own note on the status rule,
which I did not expect and so quote in full:

> "OpenRouter serves no status field of its own. Status is derived
> deterministically from `expiration_date`: absent -> active; in the past ->
> retired; within 365 days -> deprecated; further out -> active. The far-future
> sentinel dates the API carries (2098-12-31 on several z-ai rows, observed
> 2026-08-28) therefore read as active, which is what they mean — deriving
> `deprecated` from a sentinel would fire a false lifecycle timeline event on
> the joined entry."

Also confirmed the alias_target the sentence relies on is present as quoted:
`~z-ai/glm-flash-latest` carries
`alias_target: {"name":"Z.ai: GLM 5.3 Flash","slug":"z-ai/glm-5.3-flash"}` and
the description "This model always redirects to the latest model in the GLM
Flash family." — both verbatim.
