**Claim: the rule is absent → active, past → retired, within 365 days →
deprecated.** `pulse/lib/diff.mjs:116-126` (`deriveStatus`): `if (!expires)
return 'active'; ... if (daysUntil < 0) return 'retired'; if (daysUntil <=
(rule.deprecated_within_days ?? 365)) return 'deprecated';`. The registry entry
(`data/sources/registry.json:66-71`) declares `deprecated_within_days: 365` and
its `note` states the same rule in the same words. The annotation's parenthetical
omits the rule's fourth branch (further out → active), which is what keeps the
2098-12-31 sentinels on other z-ai rows reading `active`; it does not misstate
any branch it does give, and 2026-09-10 is six days out, so this is no sentinel.

**Claim: `retired` once 2026-09-10 passes.** Same function: on 2026-09-10
`daysUntil === 0` → still `deprecated`; on 2026-09-11 `daysUntil === -1` →
`retired`. "Once it passes" is exactly right.

a dropped date.** This is the only claim I thought might overreach, so I checked
it two ways. `data/changes.jsonl` carries six status flips in its whole observed
