`downloadsAllTime` is absent from both payloads — `downloads` is the only
figure the API offers, which is why "not cumulative totals" is the right
qualifier to carry. The rendered model page confirms the window in the
platform's own words: a grep of the fetched HTML (340,388 bytes) returns
`Downloads last month` and `1,231`, i.e. the page labels the same 1,231 as a
last-month figure. So "Hugging Face's rolling 30-day download counts, not
cumulative totals" is supported by the source the piece already cites.

The surrounding unchanged claims hold against the same fetch: "latest update
26 August" matches the conversion's `lastModified`; "created 18 August" matches
the source repo's `createdAt`; and 94,564 / 1,231 = 76.8, log₁₀ ≈ 1.89, which
"roughly two orders of magnitude" fairly describes.
