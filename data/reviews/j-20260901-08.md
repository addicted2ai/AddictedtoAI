**Scope.** `git -C <worktree> diff --stat HEAD~1 HEAD` prints
`data/changes.jsonl | 1 +` / `1 file changed, 1 insertion(+)`. One appended

outside the stated outcome.

**Key.** The annotation's `annotates` value is
`openrouter-models|13514954c61b0211|a9e815e403b4d7a5|nex-agi/nex-n2-mini|status`.
Line 113 of `data/changes.jsonl` carries exactly that key, `"field":"status"`,
`"old":"active"`, `"new":"deprecated"`, dated 2026-09-01. The annotation is
keyed to the change it interprets.

**The expiration_date claim — measured, not assumed.** Read the same row out of
both retained snapshots:

```
previous 2026-08-31  ... "expiration_date":null,  ... "id":"nex-agi/nex-n2-mini" ...
latest   2026-09-01  ... "expiration_date":"2026-09-04", ... "id":"nex-agi/nex-n2-mini" ...
```

Nothing else on the row moved: `pricing.prompt` `0.000000025`,
`pricing.completion` `0.0000001`, `context_length` `262144`, `created`
`1782312964` are byte-identical across the two. So the status flip is entirely
attributable to the gained date, as the annotation says.

**The rule.** `data/sources/registry.json`, `openrouter-models.status_rule`:
`{"kind":"expiration_date","path":"expiration_date","deprecated_within_days":365}`
with the note "absent -> active; in the past -> retired; within 365 days ->
deprecated; further out -> active". `pulse/lib/diff.mjs:116-132` implements
exactly that: `if (!expires) return 'active'`, `if (daysUntil < 0) return
'retired'`, `if (daysUntil <= 365) return 'deprecated'`. The annotation's
parenthetical "(absent -> active, within 365 days -> deprecated)" is a faithful
excerpt, and "the same rule derives `retired` once 2026-09-04 passes" is right
including its boundary — on 2026-09-04 itself `daysUntil` is 0 and the row is
still `deprecated`; it becomes `retired` the day after.
`pulse/tests/diff.test.mjs:123-127` asserts the same four branches.

**"presents `deprecated` (feed-bound `$status`) on its built page" — this is the
claim most worth distrusting, because `content/wiki/model/nex-agi-nex-n2-mini.md`
front matter literally says `status: active`.** It survives. `lib/facts.mjs`
`currentStatusOf` (l.176-189) resolves the feed-bound `status` fact first and
