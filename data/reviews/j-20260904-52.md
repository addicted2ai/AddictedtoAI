## The guard rail, tested by attempting what it forbids

**The no-widening guard is the one this change could most easily have broken,
and it holds — I checked the source of the distinction, not just the test.**
`assertIngested` fires on ANY recorded `last_error`, so making it carry the
marker unconditionally would have made the Desk retry deliberate, reproducible
fixture failures. The diff splits on `/^HTTP \d/`. I traced where
`last_error.detail` can come from: `pulse/lib/sources.mjs:247` sets it to
`res.error`, and `fetchSource` produces exactly two shapes —
`` `HTTP ${res.status} ${res.statusText}` `` at line 163 for a non-ok response,
and `describeFetchError(err)` at line 167 from the `catch`. The `try` block
contains only `fetch` and `res.text()`, no parsing, so the catch is reachable
only from a genuine transport/timeout condition. The split is therefore
exhaustive and exact, not a heuristic: non-HTTP detail ⟺ the fetch itself
failed. It is also the same rule `assertNoTransportFailure` already applied, so
this makes the two emitters consistent rather than inventing a new boundary.
The test `an HTTP status from that site carries NO marker` drives the real
`assertIngested` with `'HTTP 403 Forbidden'` and passes.

**The scanner's reach, measured rather than assumed.** I dropped a file into
`pulse/tests/` containing `'This is the machine failing, not the diff'` — a
third emitting site inventing a wording that avoids the tail the scanner keys
on (`/failure, not a logic failure/`) — and the guard stayed green:

```
✔ `pulse/` carries no hard-coded wording of the machine-failure sentence
ℹ tests 1   ℹ pass 1   ℹ fail 0
```

So the scanner catches the copy-paste family, which is the failure mode that
actually occurred, and not an arbitrary re-invention. **This is not a defect in
the diff**: the in-diff wording is scoped correctly ("carries no hard-coded
wording of *this sentence*"), no JS mechanism can compel a new file to import a
constant, and the failure mode is fail-closed — an unmatched wording means no
retry, i.e. today's behaviour, not a new hazard. Recording it because a later
reader should know the guard's actual radius. (Probe file deleted; tree clean.)

## The design decision, and its stated premise

`TRANSPORT_FAILURE_MARKER` stays in `loop/lib/gates.mjs` and
`pulse/tests/helpers.mjs` imports it. The justification is written into the
code, not only into RESULT.md, and its load-bearing factual claim is true. The
brief asserted this would be the first `pulse/ → loop/` import edge. It is not:

```
$ grep -rn "from '\.\./\.\./" pulse --include=*.mjs
pulse/tests/curriculum-queue.test.mjs:31: import { JOB_TYPES } from '../../loop/lib/config.mjs';
pulse/tests/indexnow.test.mjs:39:         from '../../lib/asset-routes.mjs'
pulse/tests/indexnow.test.mjs:40:         from '../../lib/site-config.mjs'
pulse/lib/indexnow.mjs:101:               from '../../lib/asset-routes.mjs'
pulse/lib/indexnow.mjs:102:               from '../../lib/site-config.mjs'
```

`curriculum-queue.test.mjs:31` is the same shape — a constant imported into a
Pulse test from `loop/lib/` — so this is the second such edge, exactly as the
comment at `gates.mjs:46` says. What the separation protects is untouched:
nothing under `pulse/lib/` or `pulse/run.mjs` imports the new constant, and
`loop/lib/gates.mjs` imports only `node:child_process`, `node:fs` and
`node:path`, so the Pulse test suite acquires no package dependency. The
rejected alternatives (emitting side owns it; one shared regex; a sixth
top-level directory; `lib/`) are each argued rather than listed, and the regex
option is rejected as a decision with a reason, which is what the brief asked
for.

The author also noticed that the brief's premise came from `loop/lib/dates.mjs:21`
("ZERO. Not one import, in either direction", measured 2026-08-31) and that
`pulse/lib/indexnow.mjs` has since made it false — and filed that as its own
bead (`addictedtoai-8tr0`) instead of quietly correcting a number whose file's
whole argument rests on it. That is the right call and the right place for it.
