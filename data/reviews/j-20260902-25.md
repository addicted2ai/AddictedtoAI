## The one required change

**`content/wiki/model/tencent-hy4-preview.md`, first timeline row.** It reads:

```yaml
  - date: "2026-08-28"
    event: "released and open-sourced under the Apache License 2.0, with instruct weights and an FP8 variant published on Hugging Face, ModelScope, GitCode and CNB"
    source_url: "https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/"
```

The cited press release does not say any of the specifics. I fetched it
(`200`, 165,080 bytes) and searched the raw HTML — scripts included, no
truncation:

```
$ grep -o -iE "Apache|Hugging Face|ModelScope|GitCode|CNB|FP8" .review-fetched/press.html
No matches found
```

The rest of that grep family confirms the instrument was working on the same
file: `grep -o -iE "[a-z-]*improvement[a-z-]*"` returns `3 improvements`,
`1 self-improvement`, and `grep -o -iE "0\.8[0-9]+|834"` returns `1 0.834`,
`3 834`. I then stripped the page to text and read all 37 paragraphs. What the
announcement actually says about openness is:

> "Tencent has released and open-sourced Tencent Hy4 preview, a
> next-generation large language model with 770B total parameters and 49B
> active parameters, and a context window exceeding 1M tokens."

> "Hy4 preview is now available as an open-source model and can also be
> accessed globally through WorkBuddy and CodeBuddy, as well as Yuanbao, ima
> and other Tencent products. Users can try the model directly through these
> applications, or connect to it via API through Tencent Cloud TokenHub and
> OpenRouter."

No licence is named anywhere on the page, and no distribution channel outside
Tencent's own products, TokenHub and OpenRouter. So the row cites one document
for four claims that document does not make — the licence, the FP8 variant, and
the Hugging Face / ModelScope / GitCode / CNB publication.

This matters more than a stray URL because it is the entry's headline claim and
because the body specifically boasts of the opposite discipline: "this entry
takes that from the LICENSE file in the repository rather than from the banner
on the model card." The fact layer honours that — `license` cites
`.../blob/main/LICENSE`, `open_weights` cites the model card — and then the
timeline undercuts it by hanging the licence on a press release that never
names one. A reader auditing the most checkable line on the page finds exactly
the vendor-said-so citation the entry is written to avoid.

**Fix:** keep the press release as the source for what it does support — released
and open-sourced on 2026-08-28 — and carry the Apache-2.0 / FP8 / four-channel
claims in a separate row (or rows) sourced to the documents that state them
verbatim. Both are already fetched and quoted below and are the sources the
entry's own facts use.

## Fix these in the same pass (not separately blocking)

1. **"No measurement accompanies either claim on the announcement" is not
   accurate for the second claim.** The announcement reports one: "These
   improvements increased end-to-end throughput by 31.8% compared with the
   baseline, with consistent gains across different context lengths and
   concurrency levels." What is absent is the method, the identity of the
   baseline, and any independent check — which is the true and stronger
   sentence. As written, the entry says the announcement carries no measurement
   while quoting its measurement two lines above.
2. **The `parameters` transclusion stutters.** `renderFact(..., {inline:true})`
   (`lib/facts.mjs:217`, `lib/build-content.mjs:185`) emits the fact's `value`
   verbatim, so "It is a mixture-of-experts model of
   `{{fact:…#parameters}}`" renders as "a mixture-of-experts model of 770B
   total, 49B activated per token — mixture-of-experts with a context window
   of …". Either drop the "— mixture-of-experts" tail from the fact value or
   drop it from the sentence.
3. **"Tencent's fourth-generation flagship" is an inference from the model's
   name.** The press release says "next-generation"; the model card says "a
   new-generation Mixture-of-Experts (MoE) flagship model". Neither counts
   generations.
4. The file ends without a trailing newline.

## Why revise rather than approve

Every substantive claim in this entry is true and independently checkable — I
checked them all, and the sourcing discipline in the fact layer is better than
most of what the brief asked for. The prose earns its place: the licence
comparison against Kimi K3 is a real argument no feed produces, and the
"raters who work for the same company as the model's developers" line is the
right amount of blunt about a vendor eval. That is an approve on quality.

It fails on one thing, and it is the checklist's first item: a cited source
must say what the fact says. The timeline row asserts the Apache-2.0 licence —
this entry's entire reason to exist — against a document that does not contain
the word. The fix is a few lines and the correct sources are already in the
file.
