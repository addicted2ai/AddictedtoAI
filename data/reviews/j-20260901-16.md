and only that. Concretely: drop "closed to newly registered users beforehand" and
the "full platform sunset" framing, leaving something the page supports, e.g.
`"2026-08-31 — kimi-k2.5 and the moonshot-v1 series officially retired; calls
return 404"`. Keep the `accessed: 2026-09-01` bump; it is correct for a value the
page actually carries.

One consequence to check while doing it, because the fact is transcluded into
prose: the body reads "Moonshot's platform record reads
{{fact:model/moonshotai-kimi-k2-5#api_sunset}}, and the vendor's model list has
now moved to the past tense — [the retirement quote]". If the value becomes the
retirement wording, that sentence states the same thing twice and its contrast
collapses. The sentence needs rewording in the same pass, or the value needs to
carry the sunset date alone with the retirement wording left to the quote.

Leaving `accessed: 2026-08-28` in place is the other coherent outcome, but it
returns the tree to the state the carried finding objected to, so it would need
the finding answered rather than reinstated.
