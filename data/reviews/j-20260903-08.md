### 4. THE PROPOSAL FILE IS UNTERMINATED — it will merge dead

`data/proposals/openrouter-batch-availability-tutorial.md` opens with `---` and
never closes it; the file ends at the last line of `evidence:` with no trailing
newline. The brief's contract is "front matter exactly: `---` … `---`", and the
loop depends on it:

- `FM_BLOCK` in `loop/lib/proposals.mjs` requires the closing delimiter.
  Measured: `FM_BLOCK.test(raw)` is `false` for the new file, `true` for the
  control `derived-batch-vs-sync-price-view.md`.
- At merge, `applyProposalMergeRules` stamps each kept proposal with
  `setFrontMatterKeys(raw, {proposed_by_job, proposed_by_type})`. With no
  `FM_BLOCK` match that function takes its "file with no front matter" branch
  and **prepends a second block**. I ran the repository's own function
  (verified byte-identical to the worktree copy) and re-parsed:

```
[NEW]     after stamp -> keys: ["proposed_by_job","proposed_by_type"]
[NEW]     slug: undefined type: undefined proposed_by_type: "repair"
[NEW]     "---\nproposed_by_job: j-20260903-08\nproposed_by_type: repair\n---\n\n---\ndate: 2026-09-03\nslug: openrouter-…"
[CONTROL] after stamp -> keys: ["slug","type","date","origin","noted_by","proposed_by_job","proposed_by_type"]
[CONTROL] slug: "derived-batch-vs-sync-price-view" type: "machinery"
```

`readProposals` rejects a file with no `slug` as malformed ("missing or
non-kebab-case `slug` in front matter"), so as it stands this proposal would
merge, be stamped, become unreadable, and be reported malformed on every run
thereafter — never selectable, never cooling into anything. Adding the closing
`---` (and a body, or at least a newline) fixes it. The underlying machinery
hazard is filed as this review's proposal.

The proposal's substance checks out, for what it is worth: its quotes are
verbatim from the quickstart page fetched above, "425 rows" matches the live
catalog at fetch time (the 06:00Z snapshot has 424; one row arrived after it),
66 `:batch` rows is right, and "six across the trailing three days" matches
`changes.jsonl` — five `mistralai/*:batch` retirements dated 2026-09-01
(`codestral-2508`, `ministral-8b-2512`, `mistral-large-2512`,
`mistral-medium-3.1`, `mistral-small-2603`) plus this one on 2026-09-03. Its
type is `tutorial`, so the self-amplification guard does not touch it.
