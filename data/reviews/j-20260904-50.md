## The invariant, checked against the real flow and not only the fixture

`owned` is `staged` — `recordPaths` filtered by `existsSync`, plus `sweptPaths`
and `consumedPaths` (`run.mjs:1502`). By the time the step runs, those records
are already committed by `commitJobRecords`, so `classifyWorkingTree` returns
`own: []` and the shared step would take its `nothing-owned` branch — except at
`pulse/lib/publish.mjs:632` that branch is guarded by `&& !aheadOfOrigin(root)`,
and after a merge commit plus a records commit the Desk IS ahead. The second new
test measures exactly this and reads both subjects back off the remote in one
range:

```
assert.deepEqual(arrived, ['job j-test: records (done)', 'job j-test (entry): a piece'])
```

`aheadOfOrigin`'s own doc comment at `pulse/lib/publish.mjs:317–327` was written
for this case ("A publish that follows a merge (the Desk's case) has nothing in
the working tree and everything in a commit, and refusing *that* push would
strand reviewed work"), so the declaring path was already designed to carry the
Desk; this diff is taking a door that was built rather than cutting a new one.

## The one thing I am not blocking on — and I measured it rather than reading it

Declaring `owned` does not only change the *staging*; it also moves the Desk onto
the declared branch's *refusal*. I nearly wrote that from the code path alone
(`pulse/lib/publish.mjs:527` sets `commitBlocked`, `:573` returns without
pushing, `:313` defines `foreignContent` as the dirty files under `content/`),
which is the exact defect this review exists to catch, so I ran it instead. A
throwaway probe outside this worktree built three temp repositories and called
the REAL shared step against each — **dry run only, deliberately**, because the
`commitBlocked` return sits above the dry-run block, so the refusal is decidable
with no code path that could reach a push, and none of the fixtures has a remote
at all:

```
CASE A — clean tree, declared owned:
  => {"published":false,"reason":"dry-run", ... "add (nothing — this run wrote nothing of its own)"

CASE B — one foreign dirty content/ file, declared owned:
  [commit] refusing: 1 uncommitted file(s) under content/ that this run did not write
           (content/wiki/model/someone-elses-draft.md). ...
  [publish] not pushing: the commit above stopped at `foreign-content` ...
  => {"published":false,"reason":"foreign-content","commit":{...,"foreign":["content/wiki/model/someone-elses-draft.md"]}}

CASE C — the same foreign dirty file, UNDECLARED (the behaviour before this diff):
  [publish] the caller declared no writes of its own — staging data/, content/ wholesale ...
  pulse: WARN publish will commit content/wiki/model/someone-elses-draft.md, which this run did not write
  => would run: git -C ... add data content   /   git push origin main
```

Case C is the clearest single statement of what this diff fixes: with the
pre-diff caller shape, the Desk would have committed and pushed a stranger's
half-written entry to the live site. Case B is the new condition I carried above
— correct, safe, and undocumented anywhere a future diagnosis would find it. The
probe was deleted; nothing outside `data/reviews/` remains from this review.
