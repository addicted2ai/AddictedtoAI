Both pages state in their own voice that the old slug "still answers and still serves" (4.8) / "the slug still answers, and existing requests still serve" (5). The sourcing is sound — OpenRouter's notice says exactly that, and it is quoted and cited — but the router's own endpoints API disagrees in shape: GET https://openrouter.ai/api/v1/models/anthropic/claude-opus-4.8-fast/endpoints returns HTTP 200 with the model record and an empty "endpoints" array (same for claude-opus-5-fast and claude-opus-4.7-fast; the surviving standard rows return 8, 11 and 10 endpoints respectively). Measured 2026-09-02. Nothing published resolves whether an empty endpoints list means the slug is aliased internally or genuinely unroutable, and it cannot be settled without an API key. A clause of the form "the model record still answers, though the router's endpoints listing for it is now empty; OpenRouter's notice is the authority that requests still route" would keep the reader's trust if they run the same check.
