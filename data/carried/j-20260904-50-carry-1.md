Declaring `owned` moves the Desk onto pulse/lib/publish.mjs's declared branch, which at :527 refuses on ANY uncommitted file under `content/` that the run did not declare — `commitBlocked = 'foreign-content'`, and :573 then returns `{published:false}` without pushing. This is correct and is exactly what the brief asked for, but it is a NEW outcome for the Desk: before this change a Desk publish with a stray dirty `content/` file swept it into the commit and pushed anyway. From now on a fully gated, merged, approved job can end with nothing reaching the live site because an unrelated agent left one entry dirty, and the only trace is one `commit` step line in the run log. MEASURED, not inferred: the same tree returns `{"published":false,"reason":"foreign-content"}` when `owned` is declared and `would run: git add data content` (i.e. would have published the stranger's draft) when it is not. Nothing in this diff is wrong — it fails in the safe direction, which is the direction the brief asked for. What is missing is an issue recording that the Desk's publish can now be blocked by a file no job in the run touched, so the first time it happens it is a known condition and not a fresh diagnosis.
