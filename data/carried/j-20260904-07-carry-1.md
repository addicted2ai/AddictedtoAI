verify-daybreak-defense-network-product-wording.md says "a plain `user-agent`-only fetch returns HTTP 403 (Cloudflare challenge); the successful request sent `accept-language: en-US,en;q=0.9` and `cache-control: no-cache` alongside a full Chrome UA." That did not reproduce on 2026-09-04 from this machine: a fetch sending ONLY the same full Chrome `user-agent` returned HTTP 200 with 375,911 bytes, while a fetch sending no headers at all (Node's default UA) returned HTTP 403 with 9,861 bytes. So the header that clears the challenge is the UA alone; `accept-language` and `cache-control` were not load-bearing. The fix is to restate the note as "a fetch with no browser user-agent returns 403; sending a full Chrome UA returns 200", or to drop the causal claim and record only the headers that were sent. Nothing else in the file depends on this — the retrieval it describes reproduces exactly. Note that Cloudflare gating is IP- and time-dependent, so the author may well have observed the 403 they recorded; the note is unreliable as a general instrument claim rather than dishonest.
