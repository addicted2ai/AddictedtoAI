The carried finding that prompted trimming `output_tokens_per_task` to "~48k" argued the trim "loses nothing, since the ~30% and the effort level are already in the sentences". The effort level is; the ~30% is not. `git grep -n "30%\|~30"` over content/wiki/model/google-gemini-3-8-flash.md and content/wiki/org/google-deepmind.md returns nothing, so after this diff the relative-rise figure appears nowhere in the corpus for this row. The surviving prose reads "average output tokens per task rose to ~48k", which gives a reader no way to tell whether ~48k is a large move — and the paragraph's whole argument is that it is ("What changed is the invoice per task"). llm-releases carries it plainly: "a ~30% rise in average output tokens per task (to ~48k) lifts cost per task to ~$0.58 at high reasoning". Fixed by a prose edit, not a fact edit — "average output tokens per task rose ~30%, to {{fact:...#output_tokens_per_task}}" — leaving the trimmed value alone.
