This diff adds eight `currency-literal` build warnings that did not exist before — measured with lib/currency.mjs's own findCurrencyLiterals against df9751b~1 and df9751b: content/wiki/model/anthropic-claude-opus-4-7-fast.md goes 6 -> 10 hits (new: price:$30.00, price:$150.00, price:$5.00, price:$25.00) and content/wiki/model/nvidia-nemotron-3-ultra-550b-a55b-batch.md goes 0 -> 4 (price:$0.625, price:$0.60, price:$3.125, price:$2.40). Each warning reads "state it with a transclusion, {{fact:<kind>/<slug>#<field>}}, so it stays current" — advice that is impossible to follow here, because the rows are gone: data/derived/feed-rows.json holds `"anthropic/claude-opus-4.7-fast": {"$as_of": null, "$status": null, "$vanished": true}` with no pricing key to bind to. The warnings are therefore correct-by-construction noise on every future build, and nothing in the tree says so. The corpus already has the shape for this — three standing ledgers (data/price-attribution-debt.json, arxiv-pin-debt.json, snapshot-census-debt.json) exist precisely so a permanent warning is not mistaken for an unfixed defect. A one-line note in either of those files' style, or an HTML comment on each page naming the vanished row, would fix it. Not blocking: the check is a warning by design and its own header anticipates exactly this case ("a build that failed on this would break every historical rebuild the moment a quoted price appeared in a legitimate sentence").
